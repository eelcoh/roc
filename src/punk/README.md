# punkroc

punkroc is an experiment: Roc with an Elm-like, whitespace-based syntax.
This directory holds the translator from `.punk` to ordinary Roc source.

```
-- punkroc                              # Roc
add = fn a, b ->                        add = |a, b| a + b
    a + b
total = add 1 (add 2 3)                 total = add(1, add(2, 3))
xs |> List.keepIf isGood                List.keep_if(xs, is_good)
inc = add 1                             inc = |punk_a1| add(1, punk_a1)
case r of                               match r {
    Ok v -> v                               Ok(v) => v
    Err _ -> 0                              Err(_) => 0
                                        }
type Shape = Circle F64 | Rect F64 F64  Shape := [Circle(F64), Rect(F64, F64)]
```

- `mod.zig`: the `punk` compiler module; `toRoc` is what the compiler calls.
- `translate.zig`: lexer, layout-sensitive parser and Roc emitter.
- `stdlib.zig`: arity and argument order of the builtins (from `gen_stdlib.py`).
- `interface.zig`: what punkroc knows about an imported module (step 4).
- `format.zig`: `punk fmt`, the formatter.
- `main.zig`: the `punk2roc` command line tool.
- `test.zig`: translation and formatter tests.
- `llms.txt`: the language reference for agents, generated by `gen_llms.py`
  from `llms.in.md` and the source (see "For agents" below).

## Zig

Building needs exactly Zig 0.17.1 (`minimum_zig_version` in
`build.zig.zon`). Another version fails at once, for example with
`invalid builtin function: '@backingInt'`. Check with `zig version`; on macOS
(Apple silicon):

```
curl -LO https://ziglang.org/download/0.17.1/zig-aarch64-macos-0.17.1.tar.xz
tar xf zig-aarch64-macos-0.17.1.tar.xz
export PATH="$PWD/zig-aarch64-macos-0.17.1:$PATH"
zig version
```

or `pip install ziglang==0.17.1` and `python3 -m ziglang build roc`.
Homebrew's `zig` is often another version. A shell script (`sh ...`) can
find another `zig` than your interactive shell, because it does not read
`~/.zshrc`; `test/punk/setup.sh` checks the version first.

## In the compiler

The compiler translates `.punk` files as it reads them (`CoreCtx.readFile`),
so everything after the parser sees ordinary Roc:

```
zig build roc
zig-out/bin/roc examples/punk/aoc_day2_functional.punk
zig-out/bin/roc check examples/punk/aoc_day2_functional.punk
```

`import Foo` finds `Foo.punk` when there is no `Foo.roc` next to it. A module
file starts with an Elm-style header; it becomes a Roc type module:

```
module Math exposing (double)          Math := [].{
                                           double = |x| x * 2
double = fn x ->                       }
    x * 2
```

When the module declares `type Shape` with the module's own name, that type
carries the block (`Shape := [Circle(F64), ...].{ area = ... }`). See
`examples/punk/imports/` and "Roc compatibility" below.

Error messages are about the `.punk` file, not its Roc translation. The
translator keeps a source map (where each name, literal and operator of the
translation came from), and every report about a `.punk` file is rewritten
with it before it is shown (`src/compile/punk_report.zig`): positions and
source lines come from the `.punk` file, and names are spelled as in punkroc.

```
── ✗ name not in scope ─────────────────── examples/punk/app.punk:20:9

Nothing is named notDefined in this scope.

x + notDefined
    ^^^^^^^^^^
```

A part of the translation that punkroc reordered (`xs |> List.map f` is
`List.map(xs, f)`) is shown as the whole pipeline it came from.

A syntax error in a `.punk` file is reported like the compiler's own errors:

```
── ✗ syntax error ──────────────────────── examples/punk/app.punk:7:22

There is a syntax error in examples/punk/app.punk.

Stdout.line! "hi"
                 ^

expected ')' but found 'end of file'
```

## For agents: `punk fmt`, `punk check --json`, `llms.txt`

`zig build roc` also makes `zig-out/bin/punk`, the same compiler under
punkroc's name.

**`punk fmt file.punk ...`** lays `.punk` files out in one canonical form,
without options, like elm-format: 4 spaces per indentation level, one space
between tokens (none inside `( )` and `[ ]`, one inside `{ }`, spaces around
operators), Elm's leading commas when a list is written that way, one blank
line between top-level definitions and none between an annotation and its
definition. Line breaks stay where the author put them. `--check` lists the
files that are not formatted and fails. The formatter works on tokens, keeps
every comment, and checks its own work: when the Roc translation of the
result differs from that of the original (ignoring whitespace), it leaves the
file alone and says so. `punk2roc --fmt file.punk` prints the formatted file.
The golden tests check that every file in `examples/punk/` is formatted.

**`punk check --json file.punk`** writes the problems as one JSON document on
stdout (`src/cli/punk_json.zig`): per problem the severity, a stable `code`
(`P101` for a punk rule, `P001` for other punkroc syntax errors,
`roc/type-mismatch` for what the type checker finds), the title, the place in
the `.punk` file (1-based line and column, and where it ends) and the message
as plain text. `fix` is there for a replacement text, but nothing fills it
yet. The exit code is 1 when there are errors.

**`llms.txt`** is the reference for an agent that has never seen punkroc:
the tools, the syntax, the differences from Elm and from Roc, the error
codes, the platform, the standard library's signatures and a cookbook. The
signatures are generated from `stdlib.zig`, `elm.zig` and `Builtin.roc` (as
punkroc sees them: camelCase, the value last, curried), and the cookbook
examples are files in `examples/punk/` that the golden tests run. After a
change, run `python3 src/punk/gen_llms.py`; the golden tests fail when
`llms.txt` is out of date.

## Currying and data-last pipes (step 3)

punkroc follows Elm here, on top of Roc's multi-argument functions.

**`|>` passes the value last.** `x |> f a` is `f a x`.

**Builtins take the value they work on last.** For List, Str, Try (also
spelled `Result`), Iter, Set and Dict, Roc's first argument moves to the
end: `List.map f xs`, `Str.splitOn "," text`, `Dict.insert k v dict`.
Folds take the function first, as Elm's `foldl` (`List.fold f 0 xs`), and so
does `map2` (`List.map2 f xs ys`). The fold's function gets the state last,
as in Elm: `List.fold (fn x, total -> total + x) 0 xs` (Roc calls it with
the state first; punkroc turns the lambda's parameters around, or wraps a
named function). `Dict.fold` passes key, value, state. Both orders then fit
`|>`:

```
-- punkroc                              # Roc
text                                    List.map_try(
    |> Str.trim                             Str.split_on(Str.trim(text), ","),
    |> Str.splitOn ","                      parse_range,
    |> try List.mapTry parseRange       )?
```

`Result.map`, `Result.mapError` and `Result.withDefault` are Roc's
`Try.map_ok`, `Try.map_err` and `Try.ok_or`; a type `Result a e` is
`Try(a, e)`. Other modules (U64, platform modules, packages) keep Roc's
order: `U64.pow 10 n` is `U64.pow(10, n)`. Watch out for functions with two
arguments of the same kind: `List.concat xs ys` is `ys` followed by `xs`
(`ys |> List.concat xs` reads right); `xs ++ ys` is clearer.

**Functions are curried.** Give a function fewer arguments and you get a
function that wants the rest:

```
add : I64 -> I64 -> I64                 add : I64, I64 -> I64
add = fn a, b ->                        add = |a, b| a + b
    a + b
inc = add 1                             inc = |punk_a1| add(1, punk_a1)
all = List.map (add 1)                  all = |punk_a2| List.map(punk_a2, |punk_a3| add(1, punk_a3))
```

Types are curried too: `A -> B -> C`, `A -> (B -> C)` and `A, B -> C` are all
Roc's `A, B -> C`. So are lambdas: `fn a -> fn b -> a + b` is `|a, b| a + b`.
A definition with fewer parameters than its annotation gets the rest passed
on (`pick : Bool -> I64 -> I64 -> I64` with `pick = fn b -> ...`).

How it works: Roc functions are not curried, so the translator writes partial
applications as lambdas. It knows the arity of the builtins above and of every
function defined or annotated in the same file or in an imported module (see
below). Arguments of a partial application that are not plain values are
computed once, before the lambda. Calls to functions it knows nothing about
(lambda parameters, record fields) pass all
arguments at once, as in Roc; partial application of those does not work.
See `examples/punk/currying.punk`.

## Folds instead of loops

punkroc has no `var`, `for`, `while` or `return`. A loop is a `fold`, a
keyword whose parts have names, so there is no argument order to remember:

```
fold xs into 0 with fn x, total -> total + x     List.fold(xs, 0, |total, x| total + x)
xs |> fold into 0 with add                       (the list comes from the pipe)
```

The block form names the accumulators in its header and has the body below:

```
fold x in xs into total = 0
    total + x

fold (i, x) in List.mapWithIndex (fn x, i -> (i, x)) xs into bestI = 0, bestX = 0
    if x > bestX then { bestI = i, bestX = x } else {}
```

With one accumulator the body gives its new value. With more, the body gives a
record with only the accumulators that change (`{}` when none does), like
Elm's `{ s | ... }` without the `s |`, and the fold's value is the record with
all of them. Both forms become `List.fold`. Effects in `main!` stay as they
are: one line per `!` call.

## Roc compatibility (step 4)

punkroc and Roc modules can use each other. When a `.punk` file imports a
module, the translator reads that module first (`Foo.roc`, or else
`Foo.punk`, next to the file; `pf.Stdout` in the directory of the platform
the app header names) and learns its functions and their arity.

**punkroc modules from punkroc.** Their functions can be partially applied
(`List.map (Math.add 10) xs`), and the `exposing` list counts, as in Elm:

```
module Math exposing (add, Shape(..), Color)
```

`Math.square` in another punkroc file is then an error ("Math does not
expose square"), and so is `Math.Red` (`Color` is exposed without its tags).
The module itself must define everything it exposes.

**Roc modules from punkroc.** Their functions get the same treatment as List
and Str: Roc's first argument, the value the function works on, comes last.
`Text.repeat 3 "ab"` is `Text.repeat("ab", 3)`, so `"ab" |> Text.repeat 3`
works, and so does partial application. Names are written in camelCase
(`Text.withPrefix` is `with_prefix`). `import Text exposing [repeat]` works
the same for the unqualified name. punkroc finds the arity in the module's
annotations (`repeat : Str, U64 -> Str`) or lambdas (`|s, n| ...`).

**punkroc modules from Roc.** To Roc, a punkroc module is an ordinary type
module with snake_case names: `Math.sum_of_squares(xs)`. Functions keep the
argument order they have in punkroc, and curried types are Roc's multi-
argument functions (`add : I64 -> I64 -> I64` is `Math.add(1, 2)`). Roc does
not check punkroc's `exposing` list: from Roc, everything is visible.

**Packages given by URL.** Their modules are Roc modules too, and get the
same treatment: `w: "https://.../Hs2w....tar.zst"` in the app header and
`import w.Wrap` make `"hi" |> Wrap.surround "<" ">"` and
`List.map (Wrap.surround "(" ")")` work. The translator reads the package
from Roc's package cache (`~/.cache/roc/packages/<hash>/`); when it is not
there yet, the compiler downloads it first, as it would right after anyway.
This works for the app file the compiler builds or checks; with
`--replace-dep`, or in `punk2roc`, which only translates a file, URL packages
keep Roc's order and take all their arguments at once.

The switch `rotate_roc_modules` in `translate.zig` turns the reordering for
Roc modules off.

`examples/punk/imports/` has all three directions: `app.punk` uses the
punkroc modules `Math` and `Shape`, the Roc module `Text.roc`, and
`Report.roc`, a Roc module that uses `Math.punk`.

## `try` instead of `?`

A call that may stop the function with an `Err` starts with the word `try`,
so the early exit is visible at the front of the line instead of hidden in a
trailing `?`:

```
-- punkroc                              # Roc
x = try U64.fromStr a                   x = U64.from_str(a)?
Ok (try parse a, try parse b)           Ok((parse(a)?, parse(b)?))
input |> try List.mapTry parseRange     List.map_try(input, parse_range)?
```

`try` takes one call with its arguments (`try f a + 1` is `(try f a) + 1`);
use parentheses for more: `try (s |> Str.trim |> parse)`. In a pipeline
`|> try f a` checks the result after piping. A postfix `?` is a syntax error
that points to `try`.

## Elm's names and types

Elm's standard names work next to Roc's (`src/punk/elm.zig`):

| Elm | in Roc |
|-----|--------|
| `List.filter`, `foldl`, `foldr`, `reverse`, `member`, `concatMap` | `List.keep_if`, `fold`, `fold_rev`, `rev`, `contains`, `join_map` |
| `List.range`, `head`, `tail`, `maximum`, `minimum`, `length`, `indexedMap`, `take`, `drop`, `singleton` | small helpers |
| `List.sortWith` | takes `LT \| EQ \| GT`, as in Elm (Roc's wants `Before \| Same \| After`) |
| `Tuple.first`, `second`, `pair`, `mapFirst`, `mapSecond` | `t.0`, `t.1`, ... |
| `Maybe.withDefault`, `map`, `andThen`, `Result.toMaybe`, `Result.fromMaybe` | helpers on `Just x \| Nothing` |
| `String.split`, `join`, `trim`, `isEmpty`, `contains`, `startsWith`, `endsWith`, `toUpper`, `toLower`, `replace`, `trimLeft`, `trimRight` | the `Str` functions |
| `String.length`, `lines`, `words`, `toInt`, `fromInt`, `append`, `concat`, `repeat` | helpers |
| `compare`, `min`, `max`, `identity` | helpers |

A helper is a short Roc definition added to the end of the translation when
the file uses it (`punk_list_head`). The file's own definitions and imports
win: a file with its own `compare` keeps it.

Types: `Int` is `I64`, `Float` is `F64`, `Maybe a` is `[Just(a), Nothing]`
and `Order` is `[LT, EQ, GT]`, unless the file defines a type of that name.
The Elm functions count with `Int` (`List.length`, `List.range`, the index
of `List.indexedMap`); Roc's own keep `U64` (`List.len`). `toInt` turns a
`U64` into an `Int` and `fromInt` back, for `List.len` and `List.get`;
`toFloat` turns an `Int` into a `Float`.

Roc's functions that may fail keep returning a `Result` (`List.first`,
`Dict.get`); the Elm-only ones return a `Maybe` (`List.head`, `String.toInt`).

## Design rules (the punk check layer)

On top of Roc, the translator enforces a few rules of its own. Each has a
stable code that starts the error message and is in `Diagnostic.code`, so a
tool or an agent can recognise it without reading the text
(`src/punk/rules.zig`):

| Code | Rule |
|------|------|
| `P101` | `crash` is only allowed inside an `expect` test. A program returns a `Result` or `Maybe` instead of stopping halfway. |
| `P102` | `dbg` is only allowed inside an `expect` test, so no debug output stays behind. |
| `P201` | Everything a module exposes has a type annotation (with `exposing (..)`: every top-level value). Apps are exempt: the platform fixes the type of `main!`. |
| `P301` | The SQL of `Sql.query` (server platform) is a string literal without `${...}`, and `Sql.query` is only used by calling it. Values go in as parameters (`$1`), so no request can change what a query does. |
| `P401` | A `table` has a record of storable columns as its rows (`Str`, `Int`, `Float`, `Bool`, `Maybe` of these), a key that is one of them, and says who may read, insert, update and delete. No rows are open by accident. |
| `P402` | A query is a pipeline from a table (`join`, `filter`, `sortBy`, `drop`, `take`, `map`, in that order) that ends in `Db.all`, `Db.first`, `Db.update` or `Db.delete` (or is a `Db.insert`), and its functions can run in the database (src/punk/query.zig). |
| `P403` | A query uses columns its table has, with values of their type. |
| `P404` | A query only does what its table's policy allows, and `Db.runAs!` and `Db.transactionAs!` are only used where a policy looks at the user. |
| `P405` | The tables are what the last version of `schema.sql` says; a changed table has a `migrate` until `punk check --schema` has added its version (src/punk/migrate.zig). |

```
Day01.punk:12:9: P101: 'crash' is only allowed inside an 'expect' test. A program must not stop halfway: ...
```

## Numbers

Provisional choice (roadmap decision 4): numbers follow Elm where Roc would
crash. Dividing an integer by zero gives 0: `7 // 0`, `7 % 0`, `modBy 0 7`
and `remainderBy 0 7` are all `0`. `modBy` and `remainderBy` are Elm's (the
result of `modBy` has the sign of the divisor, of `remainderBy` that of the
number). `a // b` is written as `punk_int_div(a, b)` in the translation.

All of this is in `src/punk/numbers.zig`; its `policy` switches back to
Roc's behaviour, the starting point if this becomes a `Result` later.
Wrapping on overflow of `+`, `-` and `*` is not done yet: the translator
does not know the types of values, and only Roc's integer types can wrap,
so `a + b` still crashes on overflow, as in Roc.

## A platform of its own

`platforms/cli` is punkroc's platform for command-line programs: `Stdout`,
`Stderr`, `Stdin.line!` and `Stdin.readAll!`, `File.read!` and
`File.write!` (only for files named on the command line), `Arg.list!`,
`Clock` and `Random`. Its host is Rust, on ambit's cli platform. See
`platforms/cli/README.md`.

`platforms/server` is for HTTP servers (`platforms/server/README.md`), and
`platforms/tui` for terminal apps in the Elm architecture: `init`, `update`
and `view`, with effects as `Cmd`s (`File.read path Loaded`), on ambit's
tui platform. See `platforms/tui/README.md` and
`examples/punk/library/` (crossload's library view).

Package names may be capitalized, as modules are: `{ Platform: platform
"...", Json: "..." }` and `import Platform.Http`, `import Json.Decode as D`.
The translator gives Roc its lowercase names (`pf`, `json`).

## Smaller Elm habits

- **Accessor functions.** `.name` on its own is `fn r -> r.name`:
  `List.map .name people`, `List.map .0 pairs`.
- **`Result.andThen`** chains steps that may fail (Roc's new `Try.and_then`):
  `grid |> List.get row |> Result.andThen (List.get col)`.
- **`Set.empty` and `Dict.empty`** are values, as in Elm (Roc's `Set.empty()`).
  So is a constant of a Roc module written as a function without arguments
  (`Cmd.none : () -> Cmd(msg)`: Roc has no polymorphic constants).
- **Tags are functions**, as in Elm: a tag of the file's own types used as a
  value (`File.read path Loaded`, `List.map2 Moved xs ys`) is a lambda that
  makes it.
- **`import Grid exposing (Grid, at)`** takes Elm's parentheses (and
  `Shape(..)`) as well as Roc's brackets.
- **A type alias with the module's name**, as in Elm: `module Grid exposing
  (Grid)` with `type alias Grid = List (List U8)`. In Roc the module itself is
  the type `Grid`, so the alias is written `Grid.GridAlias` there.
- **`==` on your own types.** Every `type` gets `is_eq` and `to_hash`
  methods (equal when the tags and their values are equal), so `outcome ==
  Loops` works and the type can go in a `Set` or be a `Dict` key, as in Elm.
- **Multi-line strings.** Between `"""` and `"""`. When the text starts on the
  line after the opening quotes and the closing quotes stand on a line of
  their own, those line breaks go, and so does the indentation of the closing
  quotes, so puzzle input can be pasted indented:

  ```
  example =
      """
      3   4
      4   3
      """
  ```

  is `"3   4\n4   3"`.

`examples/punk/aoc2024/` has several Advent of Code days written this way.

Known gaps: comments inside expressions (only comments before definitions
and statements are kept), `::` list patterns, operator sections such as `(+)`.
